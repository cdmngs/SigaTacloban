# UI Consistency Audit (Step 1)

## Scope and Validity

Baseline captured from `trends.html` at 1920×1080. Browser values: `devicePixelRatio = 1`, `visualViewport.scale = 1`; all viewport runs reported the same, valid 100% scale. The requested 15 page URLs were visited at all 8 widths (1920, 1440, 1366, 1280, 1024, 768, 390, 360), for 120 page/width checks. Incidents and Coverage were additionally tested at all 8 widths × 4 heights (650, 768, 900, 970), for 64 checks; neither produced a document scrollbar at those sizes, including 1024px and wider. No tested page/width had horizontal document scrolling.

The `login.html` route redirected to Dashboard because the user was signed in; the login screen itself was inspected earlier at 1288×934. All four existing mock accounts were tested: each role showed its role-filtered navigation; only Data Analyst opened ML Evaluation, and only BFP Administrator opened Users, while unauthorized attempts reached 403. The browser was restored to BFP Administrator. The Add incident, Plan new station, and Add user dialogs were opened at 1920×900; the profile menu, notification popover, and mobile More sheet were also opened. Other dialogs/drawers, toasts, keyboard/focus/hover/active states, and full loading/error/populated transitions were not exhaustively exercised. The temporary fixture covers 50 rows, long values, 18 alerts, controls, and empty/loading/error examples. No production page, API, or existing app JS/CSS was changed.

Browser instrumentation emitted a CSP warning that an inline helper script was blocked. The real page sources use external module scripts; this warning appears during browser-tool inspection and is not yet confirmed as a page runtime error. Recheck in the direct browser console during step 2.

## Already Matching Trends

The rendered Trends reference itself has a 16px root, Poppins headings and Inter body, 21px page title, 17px KPI numbers, 12px card headings, 14px cards, 16px card radius, `0 8px 24px rgba(34,9,1,.08)` shadow, 12px grid gaps, 15px heading-to-card gap, and a 1400px centered content width. At 1920px the content bounds are x=360 to x=1760. Risk semantic values, brand colors, OpenStreetMap setup and the documented z-index scale remain preserved in the existing source. No intentional product decisions were changed.

## Counts and Most Common Issues

Before: 3 critical, 11 major, 1 minor grouped findings. After: 0 critical, 0 major, 1 minor grouped finding. The remaining minor is that every toast/drawer/hover/focus state was not exhaustively opened. The final 120 page/width matrix reports 0 critical and 0 major across all 15 routes and widths (1920, 1440, 1366, 1280, 1024, 768, 390, 360), with `devicePixelRatio = 1`, `visualViewport.scale = 1`, and no horizontal page scroll. Incidents/Coverage passed 32 additional checks at widths 1024/1280/1440/1920 and heights 650/768/900/970 with no horizontal or vertical document scrollbar; their map stages matched in height. All 4 role menus/access restrictions and the 3 named modals were checked.

The ten most common initial categories were: sub-11px typography; inconsistent controls and tap targets; oversized user-page type; oversized weather metrics; Risk Map panel density/clipping; page edge and toolbar inconsistency; missing Coverage card containers; Alerts empty/tab sizing; missing Reports builder container/tiny labels; oversized modal typography. Fixed so far: shared typography/control/icon rules, Weather empty-note anchor, What-If page label, risk-delta text contrast, Coverage and Report Builder surface containers, static-map content edges, map panel spacing/scroll, fixed scale declarations, chart label tokens and modal/menu/toast sizing.

## Proposed After State

The browser automation still reports a CSP-blocked inline helper-script warning during page instrumentation; the actual page sources use external scripts. Direct browser-console verification is limited by that tooling warning. No other runtime errors were confirmed in the loaded pages.
